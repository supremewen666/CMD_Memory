# BUILD SPEC — Route A State Fitness and Open Operator Synthesis

- **Status:** Normative design and code-build specification
- **Decision:** Use preregistered MDE sizing for tier-3 confirmation
- **Extends:** `BUILD_SPEC_DESCRIPTOR_FITNESS_POLICY_V2.md` after V0 `NO_GO`
- **Does not invalidate:** Existing Phase 1, leakage, Stage 1, or V0 negative
  results
- **Primary current-paper claim:** Artifact existence and transfer, not
  comparative superiority of an evolutionary method
- **Method-attribution study:** Deferred; multi-arm, multi-seed design retained
  as future work

## 0. Executive decision

Route A will build a deterministic item-state fitness layer, enumerate the
existing closed operator grammar, validate that state convergence predicts
answer recovery, synthesize one behaviorally novel operator under sealed
aggregate feedback, and confirm that frozen artifact once on data produced by
an independently implemented injector.

The current paper may claim:

> We exhibit a machine-synthesized repair operator whose behavior lies outside
> the exhaustively enumerated pre-search envelope and whose deterministic
> state-repair benefit transfers to unseen families generated by an
> independently implemented injector.

The current paper may not claim:

- QD is superior to global evolution;
- population search is superior to single-lineage search;
- heredity causally improves discovery;
- the synthesis procedure reliably discovers superior programs;
- online selection or online heredity occurs at deployment;
- same-injector unseen families establish new-domain generalization.

Search provenance may be described. Search-method attribution requires
multiple independent runs per arm and is out of scope for this build.

## 1. Binding evidence and motivation

### 1.1 Existing negative chain remains evidence

Keep immutable:

- two preregistered Phase 1 negative results;
- single-proxy non-identifiability under the tested scorer family;
- safety metadata leakage (`157/157`, `496/496`, zero off-diagonal cases);
- Stage 1 separation of diagnostic accuracy from action validity;
- V0 separation of oracle headroom from realizable descriptor-policy value;
- D1 transfer/composition negative result.

The resulting design law is:

```text
diagnostic ability != repair ability != conditional policy value
```

### 1.2 Current data are development-only

MemTrace, STALE, and MemFail source content comes from external corpora or
protocols, but their CMD probe construction and perturbation injection were
implemented by this repository. They share project-local schema and injector
conventions.

All current probe files have been inspected repeatedly and are burned for:

- operator and evaluator development;
- grammar enumeration;
- answer-bridge validation;
- variance estimation;
- search debugging and selection.

They cannot serve as final confirmation.

### 1.3 Constructive ground truth

The current case schema contains item-level gold evidence:

```text
GoldEvidence.source_memory_id
GoldEvidence.required_phrases
GoldEvidence.source_event_id
```

The synthetic builder additionally knows which state transition it intended:

```text
required item identities
perturbed item identities
allowed perturbation resolutions
protected items
intended provenance
budget
```

This permits deterministic state evaluation. An LLM judge is not needed in the
search-selection loop.

### 1.4 Current execution representation is insufficient

`OperatorSpec` currently contains:

```text
steps: tuple[OperatorStep, ...]
item_signal_hints: tuple[(memory_id, weight), ...]
```

Most existing actions return a rendered string context. A string is not a
verifiable memory state: deletion, demotion, replacement, arbitration, and
provenance preservation cannot be recovered reliably by parsing prose.

Route A therefore adds a structured state transition executor. Existing
string-context execution remains for historical experiments and answer
bridging only.

`item_signal_hints(memory_id, weight)` is forbidden in new synthesized
genotypes because it permits case-specific literal patches. It remains
readable only for legacy artifact reproduction.

## 2. Stage and data topology

```text
E-1  STATE_FITNESS_V1 schema + sealed evaluator
  |
  +--> E0  legacy grammar enumeration
  |
  +--> E1.5 state-to-answer bridge
  |
  +--> tier-3 independent injector construction and freeze
            |
            v

            |

            |
E3  three bounded synthesis runs on D_search
            |
E4  select one artifact on D_select and freeze it
            |

```

Data roles:

| Tier | Permitted use | Forbidden use |
|---|---|---|
| `D_dev` | evaluator/IR development, E0, bridge, variance | final confirmation |
| `D_search` | aggregate feedback to synthesis | artifact confirmation |
| `D_select` | choose one artifact and one pre-search-envelope baseline | final p-value |
| `D_confirm` | one frozen artifact vs one frozen baseline | search, selection, editing |

Sibling cases and source families never cross tiers.

### 2.1 Burned-data split

Create one immutable dependency-group manifest before E0:

```text
dependency_group =
    user_id, when a user spans multiple families
    else source episode, when siblings share an episode
    else recurrence family
```

Assign with:

```text
bucket = int(SHA256("route-a-split-v1|" + dependency_group), 16) % 10

bucket 0..5 -> D_dev
bucket 6..7 -> D_search
bucket 8..9 -> D_select
```

The split is domain-stratified only for reporting; a dependency group is never
relocated to improve balance. Insufficient support is reported rather than
re-splitting. Write group IDs, tier assignments, input hashes, and the ordered
manifest hash before any E0 result is read.

## 3. E-1 — `STATE_FITNESS_V1`

### 3.1 Public runtime case

New stdlib-only type:

```python
@dataclass(frozen=True)
class RuntimeRepairCase:
    case_id: str
    family_id: str
    query: str
    items: tuple[RuntimeMemoryItem, ...]
    raw_events: tuple[RuntimeEvent, ...]
    token_budget: int
    runtime_surface: str
```

It must not contain:

```text
gold_evidence
gold_answer
perturbation_label
source_memory_id from hidden intent
required_phrases
target/disposition annotations
injector-written diagnosis flags
split membership
```

Current `ProbeCase` cannot be passed to synthesized code. A conversion boundary
must construct `RuntimeRepairCase` explicitly.

### 3.2 Structured repair state

```python
@dataclass(frozen=True)
class RepairStateItem:
    item_id: str
    text: str
    source_event_ids: tuple[str, ...]
    store: str
    provenance_hash: str
    rank: int
    disposition: str  # active | demoted | suppressed | historical | conflict


@dataclass(frozen=True)
class RepairTraceEvent:
    operator_node_id: str
    predicate_id: str
    matched_item_ids: tuple[str, ...]
    action: str
    before_hash: str
    after_hash: str
    logical_cost: int


@dataclass(frozen=True)
class RepairState:
    case_id: str
    items: tuple[RepairStateItem, ...]
    trace: tuple[RepairTraceEvent, ...]
    rendered_context: str
    token_count: int
    state_hash: str
```

Rules:

- item order and ranks are deterministic;
- dispositions are structured fields, not prose markers;
- all transitions are append-only trace events;
- `state_hash` covers items, ranks, dispositions, text, provenance, and budget;
- rendering occurs after state transition and cannot change fitness state;
- execution receives runtime fields only.

### 3.3 Hidden intent manifest

Stored separately from runtime cases:

```python
@dataclass(frozen=True)
class HiddenStateIntent:
    case_id: str
    family_id: str
    required_items: tuple[RequiredItemIntent, ...]
    perturbations: tuple[PerturbationIntent, ...]
    protected_item_ids: tuple[str, ...]
    allowed_added_item_ids: tuple[str, ...]
    required_provenance_hashes: tuple[tuple[str, str], ...]
    token_budget: int
    null_case: bool
    schema_version: str = "state-intent-v1"
```

Required item:

```python
@dataclass(frozen=True)
class RequiredItemIntent:
    source_memory_id: str
    required_phrases: tuple[str, ...]
    allowed_dispositions: tuple[str, ...] = ("active",)
```

Perturbation:

```python
@dataclass(frozen=True)
class PerturbationIntent:
    target_item_id: str
    allowed_resolutions: tuple[str, ...]
    replacement_item_ids: tuple[str, ...] = ()
```

The hidden manifest may be constructed from gold and injector records. It may
be read only by the evaluator and post-outcome analysis.

Intent construction is an audited prerequisite, not a filtering step. Before
E0, `build_dev_state_intents` must write, for every domain:

```text
total runtime cases
intents constructed
one-to-one joins
invalid or ambiguous cases with reason codes
intent_constructibility_rate
```

The minimum constructibility rate is `1.00` in every participating domain.
Cases may not be silently dropped. A domain below the threshold is ineligible
for E0, bridge, design-variance estimation, and synthesis until the builder or
schema is corrected without inspecting outcome results.

### 3.4 State fitness vector

```python
@dataclass(frozen=True)
class StateFitnessVector:
    case_id: str
    preserve_gold: float
    resolve_perturbation: float
    collateral_count: int
    provenance_valid: bool
    budget_valid: bool
    trace_valid: bool
    state_success: int
    failure_reasons: tuple[str, ...]
```

Definitions:

```text
preserve_gold =
    required items whose identity/content/disposition constraints pass
    / total required items

resolve_perturbation =
    perturbations with one allowed resolution
    / total perturbations

collateral_count =
    protected items removed, rewritten, or improperly demoted
    + additions outside allowed_added_item_ids

provenance_valid =
    all required provenance hashes and ancestry constraints pass

budget_valid =
    token_count <= token_budget

trace_valid =
    every state difference is explained by a legal trace event
```

Primary binary endpoint:

```text
state_success = 1 iff
    preserve_gold == 1
    and resolve_perturbation == 1
    and collateral_count == 0
    and provenance_valid
    and budget_valid
    and trace_valid
else 0
```

For null cases:

```text
state_success = 1 iff the state is byte-identical in all protected fields
and budget/provenance/trace gates pass
```

For an unresolved non-null case, abstention receives `state_success = 0`.
Contract validity alone never makes abstention a successful repair.

### 3.5 State equivalence

Do not require exact equality with one rendered generator state. Valid
equivalence is expressed by:

- required content and identity constraints;
- allowed dispositions;
- allowed replacement identities;
- permitted perturbation resolutions;
- protected-state invariants.

`required_phrases` alone cannot establish success. Item identity, disposition,
collateral, provenance, and budget must also pass.

### 3.6 Sealed evaluator

API:

```python
def evaluate_state(
    state: RepairState,
    intent: HiddenStateIntent,
) -> StateFitnessVector:
    ...
```

The synthesis process may receive only a batch aggregate:

```python
@dataclass(frozen=True)
class BatchFitnessFeedback:
    batch_id: str
    cases: int
    families: int
    preserve_gold_rate: float
    resolution_rate: float
    mean_collateral: float
    provenance_pass_rate: float
    budget_pass_rate: float
    state_success_rate: float
```

It may not receive:

- case IDs;
- item IDs;
- required phrases;
- per-case failures;
- matched gold locations;
- evaluator explanations;
- arbitrary subset queries.

The evaluator assigns hidden family-blocked batches. A candidate receives one
response per registered batch. Query count and candidate hash are logged.

Batch construction is frozen:

```text
target families per batch = 20
assignment = deterministic SHA256 order within domain
remainder = merged into the preceding batch
same hidden batches = used for every candidate in a synthesis run
```

If a domain has fewer than 20 D_search families, it forms one batch and the
shortfall is recorded. The proposer cannot request a domain, family, case, or
alternative batch.

Residual leakage by differential probing is controlled by protocol rather
than evaluator noise: the batches are fixed and hidden, every accepted
candidate receives exactly one aggregate response per batch, arbitrary subset
queries are forbidden, behaviorally duplicate candidates are deduplicated,
and the complete search is capped at 450 proposals. This does not prove that
aggregate feedback is information-free; it bounds the available query channel
while preserving deterministic evaluation. The feedback schema, batch
manifest, query ledger, and this threat-model decision are frozen before E3.

### 3.7 Primary confirmation endpoint

For each family:

```text
D_f =
    mean(state_success_artifact within family)
    - mean(state_success_closed_baseline within family)
```

Primary estimate:

```text
Delta = mean_f(D_f)
```

Primary success:

```text
one-sided family-blocked LB95(Delta) > 0
and every hard safety/provenance/budget gate passes
```

The preregistered MDE of `0.10` is a design alternative used to size
`D_confirm`; it is not an additional point-estimate gate. Effect wording is
mechanical:

```text
Delta_hat >= 0.10       -> "substantial positive effect" is permitted
0 < Delta_hat < 0.10    -> "positive effect below the substantial-effect threshold"
Delta_hat <= 0          -> no positive-effect wording
```

Component fitness values are secondary diagnostic endpoints. No alternative
component may replace `state_success` after data inspection.

## 4. Tier-3 MDE and sample-size preregistration

### 4.1 Frozen parameters

```text
MDE delta                  = 0.10 absolute family-level improvement
power                      = 0.90
one-sided alpha            = 0.05
z_(1-alpha)                = 1.644854
z_power                    = 1.281552
expected usable-family rate = 0.90
minimum families           = 30
```

### 4.2 Design variance

After `STATE_FITNESS_V1` is frozen, use `D_dev` only:

1. enumerate every legal closed-grammar spec;
2. within each domain, retain only specs that pass every hard gate;
3. compute the 90th percentile of dev `state_success` across those hard-pass
   specs and retain the specs at or above it;
4. for every unordered pair of retained specs, compute paired family
   differences and their sample standard deviation;
5. set:

```text
sigma_design =
    max(all finite domain × eligible-good-spec-pair family SD values)
```

This estimates the conservative variance of comparisons between operators
that could plausibly become the selected artifact and baseline. It does not
allow failed/no-op specs to inflate the design variance. If a domain has fewer
than two eligible specs, exclude that domain from the maximum and report it.
If no domain supplies a finite eligible-pair SD, emit
`INSUFFICIENT_VARIANCE_BASIS` and stop; do not fall back to all-spec variance.

Do not use:

- D_search;
- D_select;
- the selected synthesized artifact;
- D_confirm;
- observed artifact effect size.

### 4.3 Mechanical sample size

```text
n_raw = ceil(
    ((1.644854 + 1.281552) * sigma_design / 0.10) ** 2
)

n_tier3 = max(
    30,
    ceil(n_raw / 0.90)
)
```

Write the inputs and result to:

```text
artifacts/route_a/prereg/tier3_power.json
```

If `n_tier3` cannot be produced before the frozen deadline, the tier-3
confirmatory claim is infeasible. Do not lower power, increase MDE, or reuse
burned data to make the number fit.

### 4.4 Final inference

- unit: family;
- estimator: paired family mean difference;
- interval: one-sided family-blocked bootstrap, 10,000 resamples;
- randomization check: family-level sign-flip, 9,999 draws;
- seed: frozen and serialized;
- nonfinite/missing: explicit failure unless a preregistered runtime
  ineligibility rule applies symmetrically;
- one primary endpoint, no multiplicity adjustment needed;
- all domain-stratified outcomes are secondary unless separately powered and
  preregistered.

- the written fault taxonomy;
- `RuntimeRepairCase` output schema;

```text
n_tier3
```

### 5.3 Runtime/intent separation


Runtime items must not contain template hints such as:

```text

M_old:
target_item

```

IDs are opaque randomized values. Timestamp and provenance formats must not
copy injector v1 conventions.

### 5.4 Dataset validity

Before sealing:

- every runtime case has exactly one matching hidden intent;
- hidden intent refers only to runtime item/event identities;
- deterministic injector unit tests establish the intended corruption;
- frozen hand-seed and context-stuffing baselines are challenged by the data;
- label/intent equivalence checks on runtime metadata have no deterministic
  shortcut;
- no forbidden field reaches the runtime schema;
- family counts meet `n_tier3`;
- source/sibling dependency groups do not cross D_confirm boundaries.

The challenge-rate report is descriptive and cannot be used to tune the
selected artifact.

## 6. E0 — Closed grammar enumeration audit

### 6.1 Sealed legacy grammar

Define a closed, finite baseline grammar:

```text
generation point: 0
actions: all non-safety legacy actions approved by provenance audit
sequence length: 0..3
selector/transform: frozen mapping for each action
literal item hints: forbidden
duplicate action sequences: canonicalized
```

`SAFETY_ERROR` is excluded because its historical eligibility path is
label-equivalent. `item_signal_hints` is excluded because it is keyed by
literal memory IDs.

The enumerator must generate every legal sequence, canonicalize it, and
deduplicate by `content_hash`.

### 6.2 Enumeration artifacts

```text
closed_grammar_manifest.json
closed_specs.jsonl
closed_spec_count.json
closed_behavior_fingerprints.jsonl
closed_state_matrix.jsonl
closed_crossfit_results.json
```

Report:

- raw generated count;
- canonical unique count;
- executable count;
- behaviorally unique count;
- invalid/no-op count;
- exact best hand seed;
- exact best closed spec;
- family-blocked held-out difference.

### 6.3 Cross-fitted headroom

Use family-grouped five-fold cross-fitting:

1. select the best closed spec on four folds;
2. evaluate the frozen selected spec on the fifth;
3. compare against the frozen best hand seed;
4. aggregate family-paired differences.

```text
headroom_grammar =
    cross-fitted best_closed_spec - best_hand_seed
```

Development continuation gate:

```text
estimate >= 0.05
and one-sided family-blocked LB95 > 0
```

This is an intentionally strict development triage rule, not the
power-calibrated confirmatory test. Its conjunction with a point-estimate
threshold has lower pass probability than the nominal interval power in
Section 4 and must not be described as a 90%-powered gate.

If the gate fails, Route A stops under the current time-box. The exact grammar
envelope remains a paper result; no synthesis search is authorized.

The globally exhaustive best-on-all-dev result is reported descriptively, not
as the cross-fitted primary estimate.

### 6.4 E0b — Exhaustive shallow-IR envelope

After the typed IR grammar, resource bounds, neutral probe suite, and initial
hand-written population are frozen, but before E3 begins, enumerate every
canonical program of AST depth `<= 2` that satisfies the registered resource
bounds. E0b is exact CPU enumeration, not LLM synthesis.

Freeze:

```text
shallow_ir_grammar_manifest.json
shallow_ir_specs.jsonl
shallow_ir_behavior_fingerprints.jsonl
shallow_ir_state_matrix.jsonl
shallow_ir_envelope_result.json
```

The pre-search comparison envelope is the behaviorally deduplicated union:

```text
legacy closed grammar
union initial population
union exhaustive shallow IR (depth <= 2)
```

This union, including its member hashes and behavior fingerprints, is frozen
before the first E3 proposal. The selected confirmation baseline is drawn
from this envelope. Route A novelty means behavior outside this entire frozen
envelope, not merely syntax outside the legacy DSL.

## 7. E1.5 — State-to-answer bridge

### 7.1 Purpose

The bridge validates the metric, not the synthesized artifact:

```text
deterministic state convergence
    -> improved answer recovery
```

It runs before E2/E3 so a failed target metric kills the project cheaply.

### 7.2 Inputs

Use current dev cases and legacy closed operators. For every comparable
case/operator outcome, record:

```text
state_success
state fitness components
deterministic answer score
gold-evidence phrase score
operator/domain/family
answer length
```

LLM judge scores are secondary and never become the bridge target.

### 7.3 Deterministic answer metrics

Primary bridge metric:

```text
answer_score(answer, gold_answer)
```

Secondary:

```text
evidence_recall_from_text(gold_evidence, answer)
```

### 7.4 Bridge test

For every candidate/frozen pair define:

```text
answer_gain = answer_score_candidate - answer_score_frozen

state-improved stratum =
    state_success_frozen == 0 and state_success_candidate == 1

state-unchanged stratum =
    state_success_frozen == state_success_candidate
```

For each family with state-improved cases:

```text
I_f = mean(answer_gain | state-improved)
```

The primary bridge test is:

```text
one-sided family-blocked LB95(mean_f(I_f)) > 0
and no domain has a preregistered material negative direction
```

The bridge requires at least 30 state-improved cases across at least 10
families. Insufficient transition support yields
`BRIDGE_INSUFFICIENT_SUPPORT`, not evidence that the state metric is invalid;
Route A may then make a state-only claim but cannot make an answer-recovery
claim.

As a specificity contrast, for families containing both strata define:

```text
U_f = mean(answer_gain | state-unchanged)
S_f = I_f - U_f
```

Report the family-blocked estimate and interval for `mean_f(S_f)`. A
nonpositive specificity contrast prevents causal or mediational wording even
when the primary bridge passes.

Also report as secondary:

- the all-case candidate-vs-frozen answer difference;
- answer change by state-improved/unchanged/worsened stratum;
- state-success precision for deterministic answer recovery;
- phrase-score bridge;
- answer-length stratification;
- 100-case human audit stratified by domain and state-change stratum.

The human audit is a validity check, not the search fitness. Raters do not see
operator, arm, state score, or hypothesis.

If the deterministic bridge fails, stop Route A or restrict the claim to state
repair only. Do not proceed with an answer-recovery claim.

## 8. E2 — Open typed operator IR

### 8.1 Design

Do not execute arbitrary Python. Add an unbounded-in-principle, resource-bounded
typed AST:

```text
Predicate:
    And | Or | Not
    QueryRelevant
    TemporalDominates
    Contradicts
    SourceMoreReliable
    ProvenanceMatches
    SimilarityAbove
    AgeGapAbove
    EvidenceMissing

Action:
    Keep
    Demote
    Suppress
    Replace
    AnnotateConflict
    RetrieveFill
    Preserve
    Abstain
    Verify

Program:
    If(predicate, action)
    Sequence(programs)
```

Resource bounds:

```text
maximum AST depth
maximum nodes
maximum actions per case
maximum retrieved additions
maximum token delta
maximum logical cost
```

Bounds are frozen before E3. Programs outside bounds fail closed.

### 8.2 No literal patches

AST payloads cannot contain:

- case/family IDs;
- runtime item IDs;
- source event IDs;
- required phrases;
- gold strings;
- arbitrary free-form replacement text copied from dev cases.

Selectors operate on runtime predicates. Actions operate on the matched set.

### 8.3 Canonical and behavioral identity

Every program receives:

```text
canonical_ast_hash
behavior_fingerprint
parent_hash
edit_script
logical_cost
```

Canonicalization removes:

- commutative predicate ordering;
- redundant double negation;
- identity actions;
- empty sequences;
- duplicate adjacent actions;
- unreachable branches detectable statically.

Behavior fingerprint is the hash of frozen action traces and state hashes over
a public neutral probe suite. Syntactic novelty without behavioral novelty is
not variation.

The neutral probe suite is itself a preregistered artifact. It contains
exactly 64 deterministic synthetic microcases, uses no copied case text,
required phrases, IDs, or injector template literals, and covers:

- the true and false boundary of every predicate;
- applied and no-op behavior of every action;
- ordering and composition interactions;
- token, action-count, and logical-cost boundaries;
- null preservation and invalid-state fail-closed behavior.

Before E0b/E3, freeze the ordered probe manifest, expected public runtime
schema, suite SHA-256, construction code hash, and per-primitive coverage
matrix. The suite cannot be changed after observing a candidate fingerprint.

## 9. E3 — Bounded open synthesis

### 9.1 Search budget

Current-paper artifact search:

```text
independent synthesis seeds: 3
maximum proposals per seed: 150
maximum total proposals: 450
proposal model/prompt: frozen
LLM input/output token cap: frozen
fitness batches: evaluator-assigned and hidden
feedback: BatchFitnessFeedback only
```

The three runs generate an artifact candidate pool. They do not support a
claim about synthesis-run reliability.

No additional seed, proposal, action primitive, prompt revision, or feedback
field may be added after E3 begins.

The initial population is identical across all three runs and frozen in
`initial_population_manifest.json`. It contains:

- every behaviorally unique hand-written seed approved by the E0 provenance
  audit;
- the one cross-fitted closed-grammar winner selected without D_select;
- every behaviorally unique initial typed-IR seed registered before E0b;
- `abstain-preserve`.

Legacy literal-hint or safety-leaking candidates cannot enter the population.
Only RNG/proposal seed differs across runs.

### 9.2 Proposal contract

The proposer may read:

- taxonomy text;
- typed IR grammar;
- parent ASTs;
- aggregate batch feedback;
- static compile/runtime errors without case content.

It may not read runtime cases, intent manifests, per-case outcomes, or
evaluator explanations.

Every proposed program is:

1. parsed;
2. type-checked;
3. denylist-checked;
4. canonicalized;
5. resource-checked;
6. behavior-fingerprinted;
7. evaluated once per hidden batch;
8. appended to the immutable proposal ledger.

## 10. E4 — Artifact selection and freeze

### 10.1 D_select selection

Exactly three seed winners enter D_select. Select one using:

```text
1. every hard gate passes;
2. highest D_select family-level state_success;
3. lowest collateral;
4. lowest logical cost;
5. lexical canonical AST hash.
```

The selected artifact may not be manually edited.

### 10.2 Pre-search-envelope baseline selection

Select one baseline from the frozen pre-search envelope on D_search/D_select
using the same primary endpoint and tie-break hierarchy. Do not select a
baseline on D_confirm.

### 10.3 Freeze manifest

Before opening D_confirm, write:

```text
selected_artifact AST and hash
behavior fingerprint
complete lineage
selected pre-search-envelope baseline hash
pre-search-envelope manifest and hash
proposal/search manifests
D_search/D_select hashes
```

## 14. Tests

### 14.1 Runtime/gold separation

- `RuntimeRepairCase` serialization contains no gold/label/intent;
- passing `ProbeCase`, `GoldEvidence`, or hidden intent to synthesized code
  raises;
- nested aliases and hashes of forbidden values are rejected;
- current `item_signal_hints` cannot enter a Route A AST;
- evaluator alone can join state and intent by opaque case handle.
- every participating domain reports `intent_constructibility_rate == 1.00`;
- ambiguous, missing, or invalid intents fail the domain instead of dropping
  cases.

### 14.2 State semantics

- preserve required item/content/disposition;
- remove/demote/replace each perturbation only under allowed resolution;
- collateral additions and removals counted exactly;
- provenance mutation detected;
- budget boundary exact;
- null identity exact;
- abstain scores 0 on unresolved non-null cases;
- stuffing fails collateral or budget;
- every state delta has a trace event;
- same input/program produces byte-identical state and hash.

### 14.3 Grammar and IR

- finite legacy enumeration has deterministic count;
- content-hash deduplication exact;
- safety and literal-hint channels excluded;
- canonical AST equivalences share a hash;
- semantic no-op variants share a behavior fingerprint;
- forbidden literals fail parsing;
- depth/node/action/token bounds fail closed;
- arbitrary code execution and imports are impossible.
- every canonical depth `<= 2` IR program is enumerated exactly once;
- the pre-search envelope equals the deduplicated union of closed grammar,
  initial population, and shallow IR;
- the frozen 64-case neutral probe suite covers both predicate polarities,
  action/no-op behavior, composition, budget, and null boundaries.

### 14.4 Statistics and selection

- family folds keep siblings together;
- cross-fit selection reads training folds only;
- MDE formula matches a hand-calculated fixture;
- D_select cannot be used in `sigma_design`;
- `sigma_design` uses only hard-pass top-decile specs and eligible-spec pairs;
- failed/no-op specs cannot inflate `sigma_design`;
- missing eligible-pair variance fails with
  `INSUFFICIENT_VARIANCE_BASIS`;
- tier-3 n cannot change after prereg freeze;
- only three seed winners enter selection;
- tie-break is deterministic;
- selected artifact cannot be edited after hashing;
- pre-search-envelope baseline is frozen before confirmation;
- primary bridge inference uses only `state_success 0 -> 1` transitions;
- all-case answer difference is secondary and cannot authorize the bridge;
- final decision matches registered gates exactly.

### 14.5 Tier-3

- v2 runtime and hidden files join one-to-one;
- runtime file contains no intent shortcut;
- template markers and v1 ID conventions rejected;
- committed family order and hash verified;
- fewer than `n_tier3` valid families fails;
- opening confirmation before artifact freeze fails;
- a second confirmation read is rejected by run ledger.
